# Roster layout audit — 2026-10-06

The existing roster tiles fit. The earlier engineer-response report's claim of clipped Helix construction names and prices was a visual-review mistake. Reinspection of its full-resolution native capture and the follow-up geometry/capture checks do not support that diagnosis. No shipping layout, prices or controls changed.

## Checks and evidence

[RosterLayoutRegression.gd](../../../tests/headless/RosterLayoutRegression.gd) selects the engineer, HQ, infantry producer, vehicle producer and aircraft producer for Bastion, Helix and Frontier. It checks each roster button's horizontal bounds against the scroll viewport and the measured text, icon and theme padding against the button width. The initial headless run exits 0 with zero failures in [before.log](roster-layout/before.log). The initial scripts are retained in the evidence folder.

[RosterLayoutPreview.gd](../../../tests/rendered/RosterLayoutPreview.gd) adds rendered panel containment, tile geometry and captures at 1280×720 with 150% UI scale. Both [initial](roster-layout/rendered-before.log) and [expanded](roster-layout/rendered-expanded-before.log) runs exit 0 with zero failures and no script errors. The expanded fixture enables Coordination directly for UI coverage, gives an engineer valid 3 M / 1 E cargo and a gathering order, and pays for three ordinary tank jobs. The aircraft producer is spawned for roster coverage. These are controlled layout fixtures, not earned progression or full-match acceptance.

Expanded engineer panels remain within the 720 px viewport. The captures named `before` retain their original names; there is no production after-change comparison because no fix was warranted.

Formatting and lint pass for both new scripts. Existing navigation readback warnings appear in the runs; the initial headless run also reports ObjectDB/resource cleanup diagnostics at exit. These are retained, separate from the zero script-error/assertion results.
