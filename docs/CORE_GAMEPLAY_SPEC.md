Version 0.4 · 2026-10-01 · Design defaults for the next playable milestone

This specification resolves gaps in the [living design](GAME_DESIGN.md) using the [prototype review](playtests/2026-10-01/REVIEW.md). It describes intended behavior, not features already implemented. Values marked **tuning seeds** are inputs to experiments, not balance findings. This specification takes precedence over earlier open proposals where it explicitly settles them.

Current development priority (user, 2026-10-02): complete the playable gameplay loop before further performance tuning. The current Standard-start route and contextual guidance are verified in [the gameplay-loop report](playtests/2026-10-02/SKIRMISH_LOOP.md). Missing resource income is compared with faction armor/aircraft costs, including fitted chips; selection prefers an idle engineer and preserves construction, manual movement and queued orders.

## 1. The game we should prove next

The repeatable loop is **scout → choose an objective → assign a bounded task → commit forces → inspect the result → adapt the task or army**. Building an efficient economy supports that loop. Programming pays off when the same useful behavior survives a new situation; it should not replace choosing the next operation.

Build a two-faction testable slice before expanding the art roster: Bastion and Helix in skirmish, one Bastion programming mission, a reusable program library, and a small behavior test arena. Keep the existing all-unlocked art demo as a separate entry. Preserve the broader three-faction commitment; Free Frontier remains the third-faction direction, outside this slice.

**Success:** a player can win on Standard with shipped presets, modify one useful behavior without coding, understand why it acted, and reuse it in another match. A programming enthusiast can express something beyond the preset parameters. Both still choose where to fight, what to build, and when to retreat.

## 2. Match starts, pacing and objectives

| Start | Contents | Purpose |
| --- | --- | --- |
| Standard | HQ, four engineers, two infantry, 60 materials / 12 electronics, no lab; player assigns harvesting. | Test the conventional-to-programmable transition. Same economic start for both factions. |
| Advanced | HQ, generator, infantry producer, vehicle producer, lab, service building; four engineers, two infantry, two basic vehicles and one repair robot; 120 M / 60 E; basic chips fitted to compatible starter machines. | Let returning players use saved programs immediately. Requires sufficient power at spawn. |
| Art review | Existing generous Bastion roster and separate Helix viewer. | Inspect assets and controls; excluded from pacing conclusions. |

**Pacing hypotheses:** first scout/contact in 1–2 minutes; basic chips around 3–5 minutes; first expansion around 6–10 minutes; ordinary skirmishes 20–30 minutes, campaign operations 15–35. These replace the earlier 5–8 minute chip hypothesis: players should encounter the defining feature earlier. Do not gate chips with an artificial minimum timer. Track fast, typical and struggling build orders before tuning costs to these targets.

The initial skirmish rule is **Command defeat**: destroy all completed enemy HQs, then maintain that state for 60 simulation seconds. A replacement completed HQ resets the countdown; foundations do not pause it, so repeated cancelled blueprints cannot prevent defeat. The 45-second HQ build seed leaves a recovery opportunity for a nearby engineer with funds. Each side receives the same recovery rule and visible countdown. With no owned units or structures, defeat is immediate. A simultaneous defeat is a draw. The countdown reveals the loss condition, not hidden enemy locations. Optional annihilation can remain for sandbox play, but is not the default: an unarmed drone must not prolong an already decided match.

Campaign objectives override the skirmish rule and state their loss conditions explicitly. Killing every enemy is optional unless the briefing says otherwise. Results offer replay, return to campaign/skirmish setup, and program-library access. Never continue spawning waves after victory.

## 3. Economy, production and recovery

### Acquisition and spending

Use two stockpiles and one capacity: **materials**, **electronics**, and **power**. Both resources use the same engineer and HQ drop-off loop. No electronics-only refinery in this slice; the rarer resource and travel exposure already create a meaningful choice. Wreck salvage belongs to the later Frontier faction experiment, not the shared opening economy.

Workers carry four units of one resource. Preserve the initial collection seeds of one second per material and two per electronic, then tune transport distance. A field has three material nodes and one electronics node, initially two work slots per node. Extra workers wait visibly; the UI reports active/waiting workers. The player assigns a field and resource type. Exhaustion selects another node of the same type in that field; if none remains, return cargo and request a new assignment. Never silently switch resource type or drive to a remote contested field. Losing the drop-off stops the trip with a notification; the player can select another known friendly HQ.

Implemented field boundary: same-type deposits within 10 metres of the originally clicked deposit, fixed for the lifetime of that assignment. It never moves with the worker, HQ or replacement node. A work slot is reserved while approaching/collecting and released while returning cargo. Full nodes make extra workers wait in place and retry every 0.5 simulation seconds. A new resource order first delivers any carried cargo. Completed deliveries hand off queued orders; depleted or missing-HQ waits also accept later Shift orders. Human terminal waits appear in the idle-engineer shortcut; AI commanders may explicitly reassign their own workers. This local-radius definition is the current map contract, rather than separately authored field IDs.

Map stockpile seeds: each home field totals 600 M / 240 E; each expansion 900 M / 400 E. They are finite and their remaining amounts are visible when inspected. Starting placements must sustain the full basic-chip build path without forcing a contested capture. Electronics-rich expansions provide Helix a reason to leave its base. No passive infinite income or new harvestable currency.

### Power and production

- Retain 20 HQ supply, 25 per generator, and the current per-building usage as initial power seeds. Show **used / supplied**, a shortage icon, affected facilities and revised completion times.
- A shortage gives production, research, chip installation and service-building repair 35% speed. Harvesting, mobile movement, direct orders, installed chips and weapons continue normally. This avoids cascading loss of control after a generator raid.
- Each producer has one active job and four waiting jobs. Reserve full cost and one population slot when queued. Cancellation refunds 100% for this PvE slice. Producer destruction loses paid jobs and frees reservations; warn with the lost queue value. No automatic spending or repeat-build API for scripts.
- A lost prerequisite pauses the affected job with a reason; cancel/reorder remains possible. Finished units blocked at the exit wait in a visible completed-job state and keep their population reservation; they are never spawned inside geometry.
- A producer's rally follows its current assigned resource or friendly unit. Replacing that target releases the previous assignment: losing the old target cannot erase the new order. Losing the current target resets the rally to the producer. Explicit point rallies and target identities survive paused archives; factory programs retain the existing manual-rally priority. See [rally retarget verification](playtests/2026-10-07/RALLY_RETARGET.md).
- A single selected completed producer names its current rally destination and offers **Clear rally**, disabled when unassigned. Clearing affects future rally orders while preserving paid jobs and existing unit commands. Mixed-selection Stop retains its ordinary scope. See [rally control verification](playtests/2026-10-07/RALLY_CONTROLS.md).
- Construction is performed by one engineer per site, with full price reserved on placement. A blueprint is not a functioning building. Placement must retain a reachable exit and access to resource work slots. Cancellation refunds the unused fraction, rounded down separately for each currency; destruction gives no refund. Recovery guidance includes those live refunds when evaluating HQ affordability and offers explicit foundation review rather than cancelling construction automatically. Extra engineers do not accelerate construction in this slice.

## 4. Chip ownership and progression

**Basic unlock:** a completed vehicle producer plus faction lab. Bastion uses Vehicle Factory + Command Lab; Helix uses Robotics Foundry + Signal Lab. Labs require a completed vehicle producer to place. No kill quota, contested objective, extra unlock payment or LLM account is needed.

| Tier | Unlock and hardware | Available behavior |
| --- | --- | --- |
| Conventional | Start | Move, stop, attack, attack-move, hold, manual escort; basic idle fire and harvesting. |
| Basic | Vehicle producer + lab; conventional tank/Needle retrofit costs 4 E and five seconds at HQ/service building. | Unit-local state, bounded target priority, retreat/return, patrol and escort. |
| Coordination | Lab research, 20 M / 20 E and 30 seconds; existing basic hardware remains sufficient. | Explicit squads, small shared state, target claims and faction coordination ability. |

Robots, scouts, strike aircraft and long-range platforms include basic hardware in their listed price. They can execute ordinary orders before the unlock where production permits, and activate the installed preset when basic technology is available. Standard production order: infantry/engineers first; basic armor, scouts and repair robots next; walkers and strike aircraft require a lab; railgun/Prism require Coordination. Both factions gain access to static AA after the vehicle producer, before strike aircraft.

A conventional tank/Needle can be queued with “fit chip” after unlock; this adds 4 E and five seconds to its production job. Existing vehicles require an explicit service order. Charge once, not again when changing code. Cancelled installation refunds in full; a destroyed installation target loses the paid fee. No automatic replacement purchase.

Infantry and engineers remain conventional in this slice. They can be directly grouped and follow ordinary orders, but they cannot borrow a robot's script capability. The earlier Vector/Mule preset ideas are retained for a later tactical-receiver upgrade. Do not ship a confusing disabled editor on every early soldier.

Technology belongs to the current match. Once unlocked, existing chips continue working after lab destruction; new gated production/research waits for a replacement lab. Campaign progression makes a technology available to build, not automatically purchased in every battle. Saved programs never bypass a missing capability. No radio-range simulation, signal-loss freezes or arbitrary code-length tiers in this slice. “Advanced” cross-group automation is deferred until bounded squad coordination works.

### Classic unit research

A completed vehicle producer and lab also offer Weapon systems I/II (+10%/+20% total combat damage), Combat armor I/II (+10%/+20% total maximum combat HP with health percentage preserved), Field service (+25% healing) and faction doctrine. Coordination unlocks the existing signature abilities; doctrine strengthens Anchor's incoming reduction to 25% or Precision's first-shot preparation reduction to 50%. Technologies share one paid research slot with Coordination, pause without a lab and retain completed benefits after lab destruction. The selected lab and global Tech view expose costs, prerequisites, progress and cancellation refunds. [The technology contract](GAME_DESIGN.md#93-classic-rts-technology-and-conventional-opening) records the provisional prices, applicability and verification.

The program arena captures completed battle research at launch and offers an explicitly unupgraded comparison. Result labels and saved test notes retain that setup; active research, payments and live orders never enter the isolated test match.

## 5. Command authority and useful automation

### Direct-order contract

One command arbiter owns each unit's intent. Humans, presets and Lua use the same validated action interface. A script never directly edits HP, movement transforms, resources or visibility.

| Player action | Immediate result | On completion |
| --- | --- | --- |
| Move / attack / attack-move / retreat | Interrupt the program's action and enter **Manual override**; newest unqueued order replaces the prior one. | Default: hold at the outcome position. Explicit **Resume program** restarts the assignment. |
| Shift-order | Add to the manual queue, including during pause. | Resume only after the entire queue, if the player enabled **Auto-resume** for this group. |
| Stop / hold | Cancel movement and queued orders; hold permits firing in range without pursuit. | Stay manual until Resume. |
| Assign program and Run | Validate parameters and assignments; begin at the next simulation tick. | Continue inside the assignment until stopped or completed. |
| Disable automation | Preserve source/parameters, discard pending script intents. | Ordinary RTS orders and idle defense remain available. |

Scripts, including emergency-retreat rules, cannot overrule an active manual order. If the player wants automatic retreat during an attack, issue an assignment to the program instead of a direct attack command. This is visible in the UI. Auto-resume is **off by default** and saved per group. Resuming re-evaluates the current world rather than replaying stale intents. Paused edits do not advance any cooldown, gathering, construction, AI, projectile or program timer.

**Move** prioritizes the destination and does not acquire targets en route. **Attack-move** advances toward the destination, stopping for legal visible targets within weapon range and a two-metre pursuit allowance, then resumes the route. It never chases a retreating scout across the map. **Attack target** follows the explicitly selected visible enemy; on lost sight, move only to its last observed position, then hold. The selection panel exposes distinct Move [M], Attack target [T] and Attack move [F] buttons with remappable shortcuts. Choose a destination or visible enemy with left-click; the configured queue modifier appends the order. Escape/right-click cancels targeting before it changes orders. Valid older custom key profiles retain all bindings when the two new actions are added. See [direct command verification](playtests/2026-10-04/DIRECT_ORDERS.md). Ordinary idle defense may fire without moving, even during manual Hold.

Every active program requires an anchor: a player-chosen point/radius, patrol waypoints, target, or friendly escort group. Guard uses a six-metre radius seed; pursuit extends at most two metres beyond the assigned sector, then returns. The built-in Guard acquires currently allied-observed, unobstructed legal targets throughout the assigned circle, including beyond its weapon range; weapon range still limits firing. An enemy leaving the circle ends pursuit and returns the defender to the anchor. [Guard-area verification](playtests/2026-10-03/GUARD_AREA.md) covers both factions, sector limits and approach restoration. Retreat requires an explicit safe point; its path may leave the sector. Show these boundaries on selection. Reaching an inaccessible point reports **Blocked**, makes no repeated cross-map attempts, and asks for a new assignment after five seconds of no progress. An assigned ground point inside a living friendly structure explicitly asks for a clear point; enemy geometry and combat approaches do not feed that diagnostic. New archives preserve the last Lua guard intent so blocked guard boundaries remain visible while paused after loading. [Blocked-assignment verification](playtests/2026-10-04/BLOCKED_ASSIGNMENTS.md) covers captured/fresh faction recovery and mouse reassignment. A built-in preset safe point placed inside a completed friendly matching service building uses its existing five-metre service area: the unit stops, receives ordinary bounded service and returns at its configured health threshold. Lua and visual-rule movement to the assigned safe point uses the same arrival rule; the authored program retains control of its recovery and return conditions. This avoids treating the building’s inaccessible center as a failed route. Map assignment input preserves this service-building exception: ground safe points may target completed compatible owned facilities, while unsuitable/unfinished owned footprints and ground guard/patrol points are rejected before changing programs. See [service assignment verification](playtests/2026-10-07/SERVICE_ASSIGNMENT.md). Ground points outside that footprint remain exact assignments; unsuitable, enemy, unfinished or lost facilities do not relocate the chosen point or grant healing. Manual Stop/replacement and tactical pause retain priority. [Facility-recovery verification](playtests/2026-10-04/PRESET_RECOVERY.md) covers both factions, all six programmable mobile roles, crowded service and partial-healing archives. Navigation may try one alternate route before that notification.

Ground guards returning to an occupied center can settle beside a stationary friendly mobile unit within one metre of that center, or an already settled guard of the same assignment. Neighbor contact uses their combined radii plus 0.25 m, remains inside the original circle and requires a clear connection. Moving/enemy/air units, stale assignments and owned-structure anchors do not extend formation arrival. Target acquisition retains priority; membership is rebuilt after save/load. [Guard-arrival verification](playtests/2026-10-04/GUARD_ARRIVAL.md) covers captured traffic, all three authoring modes and the remaining building-corner/AI coordination failures.

Ground recovery tries a terrain-clear side route for at most two seconds or two metres, then resumes the same destination. Swept ground contact limits steps and allows a clear tangential slide; occupied friendly endpoints retain short yielding and existing order-specific completion rules. Archive loading waits for obstacle initialization and publication of the final region/map before restoring control, without advancing saved clocks. A program decision evaluates valid arrival/formation/combat before applying the unchanged five-second trip timeout. [Corner-recovery verification](playtests/2026-10-04/CORNER_RECOVERY.md) covers the original blocked guards, recovery archives and arrival timing; the subsequent [route-end correction](playtests/2026-10-04/ENDPOINT_TAIL.md) resolves the separate captured Industrial plain-Move blockage. Plain Move now bounds remaining path travel by the two units’ radii plus 0.2 m rather than requiring the final path index. Existing stationary-friendly occupancy, proximity and two-second no-progress checks still apply. Long detours cannot finish merely because the endpoint is nearby. New archives retain this arrival observation; legacy archives initialize it on resume.

New Lua and visual Guard & regroup starters use bounded six-metre area defense: keep a legal firing position, approach currently observed legal enemies inside the assignment, and return when they leave. The script chooses recovery/retreat; existing saved source retains its behavior. Visual rules expose Defend assigned area and Lua exposes `guard`, with no script-chosen target, point or radius. [Authored guard verification](playtests/2026-10-04/AUTHORED_GUARD.md) covers crowded fire, both-faction armed roles, legacy records, real approach archives and the still-open mixed-force/pacing outcomes.

### Presets and group behavior

Ship three defaults per compatible combat role where useful: **Hold**, **Escort**, and its specialist behavior (standoff, strike-return or fire support). Scout gets assigned-route patrol and follow-group. Repair gets bounded escort-repair and hold-service-area. Units are usable immediately with Hold; presets requiring an assignment remain **Waiting for assignment**, not silently roaming.

Default retreat/return thresholds are 30%/80% HP, editable in five-point increments. Show the current reason: “Retreating: 24% HP < 30%” or “Holding: target left sector.” If no repair/safe point exists, hold and request one; do not invent a route into unknown territory.

Squads are logical groups of individually selectable units. A unit belongs to at most one program squad, but may appear in multiple numeric selection groups. Selection groups do not grant shared memory. Membership changes are explicit, dead members are removed, and replacements are not auto-bought or auto-enrolled. Default squad size recommendation is 4–12, with a 24-member implementation cap for this slice. Unchipped members accept human group orders only; the squad panel shows how many members can run the doctrine.

Formation is soft spacing, not perfect rigid choreography. Ground and air travel independently; vehicles should not block indefinitely waiting for a faster aircraft. Narrow routes compress formation and restore spacing beyond the obstacle. A plain ground Move can finish beside a settled friendly unit occupying its final reachable position after two seconds without useful progress, within the combined body radii plus 0.2 m. This does not finish distant routes or contact work; queued orders continue normally. [Crowded-destination verification](playtests/2026-10-04/CROWDED_DESTINATION.md) preserves the original full-match capture and disk/renderer checks. The player chooses the rally point, composition and commitment; programs do not select expansions, objectives, production, research or squad membership.

## 6. Combat, counters and sustain

### Shared rules

Use armor tags **infantry / light machine / heavy armor / structure** plus a separate ground/air target domain. No facing armor, suppression, fuel, ammo logistics, garrison interiors, veterancy stat stacking, cloaking or naval pathfinding in this slice. Aircraft hover/VTOL in gameplay even when their silhouettes resemble fixed-wing aircraft. Weapon cooldown is sufficient to limit sorties initially; “return” means a chosen regroup point, not a hidden rearm requirement.

A weapon must pass domain, range, current allied visibility and line-of-fire checks at firing time. Opaque cliffs/buildings block direct fire and ground vision; air navigation can cross them, but air units use their own elevated sight checks. An obstruction does not become transparent because a script selected the target. No blind fire in the first slice. Cover bonuses are deferred; urban maps still change combat through sight blockers and approaches.

One weapon profile plus armor multipliers is the first counter model; no second hidden armor-subtraction formula. Final damage = base damage × profile multiplier × active Anchor factor (0.85, otherwise 1), accumulated without rounding every fractional hit away. Unsupported air/ground targets are rejected before damage calculation.

| Weapon profile | Infantry | Light | Heavy | Structure |
| --- | --- | --- | --- | --- |
| Rifle | 1.0 | 0.6 | 0.15 | 0.15 |
| Autocannon | 1.25 | 1.0 | 0.45 | 0.35 |
| Tank cannon | 0.5 | 1.0 | 1.0 | 0.7 |
| Precision rail | 0.4 | 1.0 | 1.4 | 0.8 |
| Anti-armor lance (Helix Precision) | 0.3 | 0.8 | 2.0 | 0.5 |
| Strike missile | 0.75 | 1.0 | 1.0 | 0.6 |
| Anti-air | Not eligible | 1.0 against air | Not eligible in this slice | Not eligible |

These are tuning seeds. Walkers count as light machines; tank/Needle/railgun/Prism as heavy armor; aircraft as light machines in the air domain. Air eligibility comes from the weapon, never from the armor multiplier. Direct hits may use immediate damage with tracer effects initially; missiles resolve on impact and are cancelled if their target no longer exists. No firing through blockers due to cosmetic projectiles.

Aim for 8–15 seconds for an unassisted equal-tier armor duel at effective range and at least a few seconds to react to ordinary focus fire. This is a measurement target, not a guarantee that all units survive any volley. Special charge attacks need visible warning. Keep current Bastion HP/damage as the starting reference; initially give Helix's comparable mobile machines about 80% HP and 120% movement speed, without increasing all their DPS. Record each actual stat in a faction catalog during implementation. Cost, movement and information advantages must be tested together; do not assume equal unit counts mean equal army value.

### Repair rules

The probe confirmed additive healing: one robot restores three HP per update, two restore six, and robot + depot restore seven. Their nominal 0.5-second cadence implies roughly 6/12/14 HP per second, against the current tank's nominal 7.5 DPS. That is sufficient reason to constrain sustain before evaluating armor matchups; it is not a measured claim that every supported tank is invulnerable.

For the next slice, only the **strongest single repair channel** affects a target. Mobile repair restores 2.5% max HP per second; a depot has two channels at 4% each. After taking enemy damage, that target receives 25% repair effectiveness for three simulation seconds. Repairs do not consume stockpiles: the cost is purchasing support, keeping it alive, time and service power. This also keeps ordinary repair programs from implicitly spending resources.

Mobile repairers stop to channel, use three-metre range, and cannot heal themselves. For completed structures, that reach is measured from the structure footprint; mobile targets keep center-to-center range. Direct orders, presets, Lua and the repair service share this rule so large buildings remain reachable. Depots use five metres and cannot stack with mobile repair. Repair robots affect mechanical ground units and completed structures; aircraft repair while stationary at their air producer, with two service slots using the depot rate. Infantry recover at their infantry producer using the same two-slot service rule. No resurrection or mid-combat chip recovery from wrecks.

## 7. Faction differentiation using the existing roster

| Tactical question | Bastion answer | Helix answer | Counterplay |
| --- | --- | --- | --- |
| Hold an exposed area | Durable tanks, infantry screens, depot-backed rotations. | Scout early, choose a firing angle, withdraw before a sustained trade. | Raid the support line or force a second front. |
| Defeat armor | Railgun tank behind the frontline. | Lancer precision mode and Prism after setup. | Infantry screening, flank the firing position, interrupt setup. |
| Defeat infantry/light machines | Combat walker's autocannon; infantry supported by armor. | Vector screens and Needle concentration; expensive air support when safe. | Avoid offering compact specialist targets and attack from multiple angles. |
| Move under air threat | Combat walker provides short-range mobile AA; missile battery protects fixed points. | Lancer switches to interception mode; Skyward covers bases. | Force the escort away or attack during stance change; aircraft cannot simply bypass every mobile counter. |
| Strike an expansion | Slower armored commitment that can hold the site afterward. | Wraith pass or skimmer raid followed by withdrawal. | Scout approach routes, reserve defense, attack the raiders' electronics supply. |

**Mobile AA closes a roster gap without another model.** Bastion's walker uses an autocannon against ground and a separate short-range AA firing profile, sharing a cooldown. Helix's Lancer has player-selected **Precision / Interception** modes; a two-second switch disables firing, Interception attacks air only, and Precision attacks ground only. Programs may prioritize targets within the chosen mode but cannot switch modes in this slice. Show the mode in the silhouette badge and command panel. Do not give every rifle/tank a universal anti-air weapon.

Implemented first pass: Bastion ground range 5.5 m and AA range 4.5 m share 5 base damage / 0.7 s reload, with autocannon versus AA armor multipliers. Helix starts in Precision (8 m, 15 base damage, 1.25 s reload, anti-armor lance multipliers), with Interception at 5.5 m / 5 damage / 0.7 s. Mode changes preserve movement and programs, reject another switch while pending, freeze under tactical pause and never reset the existing reload. Unsupported target attacks end when the new mode commits. Unit badges, mixed-selection mouse/keyboard controls, observed-contact skirmish AI and partial-switch archives are implemented. These are tuning seeds; precision wind-up and coordinated abilities below are now implemented, with encounter tuning still pending.

**Bastion signature — Anchor formation:** the player designates a sector and up to six chipped ground combatants. After two seconds stationary inside it, incoming weapon damage falls by 15% from every direction; moving leaves the benefit immediately and requires another activation to regain it. A ten-second cooldown starts on activation and buffs never stack. Programmed retreat remains possible. This expresses commitment to ground and gives artillery/flanks a reason to dislodge the group. Buff values are hypotheses; repair is still subject to the common cap.

**Helix signature — Precision window:** retain the proposed two-second window, up to six chipped participants and eight-second group cooldown. It reduces first-shot preparation by 20%, not sustained weapon reload. It needs a meaningful preparation mechanic: seed precision weapons with 0.75-second wind-up, ordinary rifles/autocannons with none. Only participants with a visible, legal target and an eligible shot receive the benefit. If testing finds 0.15 seconds unreadable, replace the effect; do not add hidden damage bonuses to make the tooltip seem valuable.

Implemented signature pass: Coordination research unlocks explicit selection commands. Anchor covers a 6 m radius; the closest six ready chipped tanks, railguns/Prisms or combat robots are selected. Units may enter afterward under existing orders, with the two-second stationary setup beginning only inside the sector. Movement after anchoring breaks it permanently until a new activation. Precision accepts stationary, deployed, reload-ready precision weapons with an observed legal target. It shortens one preparation from 0.75 to 0.60 seconds, including an already charging shot; cancellation does not refund that use. Damage and reload remain unchanged.

Activation cohorts are separate from named squads. Both participant and cohort retain cooldowns through regrouping, while disjoint ready units may activate independently. Abilities never replace orders or programs, never issue movement and cannot be invoked by unit Lua in this slice. The opponent commander issues the same commands from observed contacts. Selection controls, sector cancel, neutral sector outlines, setup/active badges, pause and snapshot-v4 restoration are implemented and verified. The perceptibility/value of a 0.15-second gain still needs player acceptance and equal-budget encounters.

**Prism:** deploy for 1.5 seconds; fire through direct line of sight after a visible charge; movement cancels setup. The Bastion railgun remains a shorter-range mobile platform. Seed Prism range at 125% of Bastion railgun range, with lower mobility and the shared visibility restriction. Avoid two differently colored copies of the same artillery unit.

Implemented preparation pass: railguns, Prism and Lancer Precision now prepare each shot for 0.75 seconds after reload. Ordinary weapons and Lancer Interception retain their existing firing cadence. Prism automatically deploys after 1.5 seconds stationary, retains deployment while holding, and retracts on a move order or displacement; Bastion railguns need no deployment. Movement, a new target, lost firing legality or changing Lancer mode cancels the current charge. Visible muzzle energy, charge percentage and unfolding Prism supports expose the delay; pause freezes it and battle archives restore exact remaining preparation. These delays reduce sustained precision DPS relative to the earlier instant-shot prototype. Group abilities are delivered; the first controlled encounter pass below tunes Lancer, while broader faction balance remains open.

First encounter tuning pass: the original 6.5 m / 9-damage Lancer failed its armor-specialist role even with a prepared firing position. ## 8. Information, programs and authoring

### Program contract

The first public API exposes immutable snapshots of self, assigned allies, currently observed enemies, known terrain/resources, orders and assignments. IDs are opaque stable handles, not engine nodes. A target leaving visibility becomes a last-known record with observation time; it cannot be attacked by ID until observed again. Remembered terrain is usable for routing, but undiscovered enemy bases and moving hidden targets are unavailable.

Expose bounded intents: hold, move to assigned point, attack a visible legal target, escort an assigned ally, retreat to assigned point, repair an eligible ally and report a status. Every intent passes the command arbiter and capability checks. No construction, production, resource transfers, dynamic squad ownership or arbitrary world queries. Stockpiles may be shown read-only for explanations; they do not create spending authority.

Start at five program evaluations per second per unit, staggered across frames. Manual commands are processed at the next simulation tick without waiting for a script interval. Cap a snapshot at 32 nearest eligible contacts with stable tie ordering; indicate truncation. Bound path queries and shared state independently of Lua instructions. Initial memory targets are 16 KiB serialized unit state and 8 KiB squad state; sandbox instruction/allocator limits require implementation measurements and a runtime dependency review. A slow program must be suspended rather than delaying the whole battle. These numbers do not establish security by themselves.

A script exception or exhausted execution budget suspends that unit's program, clears its script intents and enters Hold with normal idle defense. It never cancels a manual command. Show one deduplicated alert with unit, program version, line/reason and Resume/Edit actions. Resume starts from clean runtime state after validation; do not repeatedly auto-restart a failing loop. Missing assignment similarly enters Waiting without using a guessed target.

### Visual rules, Lua and library

The visual editor's source of truth is a versioned rule document: ordered conditions/actions, parameters, assignments and optional named states. It generates Lua. Visual mode never attempts to reconstruct arbitrary Lua. Choosing Custom Lua duplicates the version, retains the original visual draft and clearly states that freeform edits are not graph-editable. LLM generation initially produces custom Lua plus parameters and a plain-language summary; visual-rule generation is deferred.

Required editor flow: **choose preset → set anchor/parameters → simulate in arena → inspect reason trace → save version → apply to selection**. An ordinary preset adjustment does not force players through code. A valid program needs a compatible unit capability set and all required assignments. Factories pin an exact version, not “latest.” Upgrading selected units/factories is explicit and previews incompatible members before applying atomically. If a factory's selected version is missing or incompatible, new units receive the built-in Hold preset and a notification; they are never unusable.

Program records contain stable ID, version/hash, API version, authoring mode, source/rules, parameter schema, capability requirements and test notes. Store per-unit runtime memory separately. Export/import includes no credentials, local paths or live match target IDs. For another map, parameterized assignments must be rebound; saved coordinates are not silently treated as a valid mission order.

The arena supplies small tests for retreat hysteresis, escort bounds, hidden-target loss, invalid assignments, manual override, blocked paths and destroyed repair targets. Display expected outcome, actual intents and a short time trace. A passed test is evidence for that scenario, not certification that a program fulfills all natural-language intent.

### LLM workflow and privacy

Generate only on an explicit Create/Revise/Explain request. Send the supported API version, selected unit capabilities, the selected draft, relevant parameter schema and an optional bounded diagnostic trace. Exclude save files, credentials, unrelated library entries and hidden match state. Show exactly which context categories are included before the first request and let the player omit the trace.

Keep provider configuration separate from game saves and use the platform credential store. The adapter needs generate, cancel, timeout and error mapping, with a configurable endpoint/model and capability detection. Provider selection is a separate implementation spike; no current provider support is implied by this spec. A visible request budget/estimated usage precedes paid calls when supported; never invent a precise quote when the provider cannot supply one.

Response → draft summary and code → syntax/API/sandbox checks → optional arena run → explicit Apply. Never execute an arriving response automatically. Preserve the old program until Apply succeeds. On timeout, bad credentials, cancellation or invalid output, retain the player's prompt/draft and keep presets/visual editing usable. One explicit retry is sufficient; do not loop paid repair calls. LLM response time never pauses the simulation automatically or controls real-time decisions.
