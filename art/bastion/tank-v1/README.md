# Bastion main battle tank — Model v1

Status: first 3D review asset, modeled and rendered using Blender 5.2.1 background CLI. This is editable polygonal geometry, not an image projected onto a plane.

Reference: [ground-force concept sheet](../../../docs/concept-art/bastion/v1/02-ground-unit-designs-v1.png).

## Deliverables

- [Editable Blender scene](bastion_tank_v1.blend): component-level model, export hierarchy, camera, and studio lighting.
- [Godot-targeted GLB](../../../assets/models/bastion/tank-v1/bastion_tank_v1.glb): self-contained geometry and PBR materials, with three consolidated rigid meshes.
- [Build script](build.py) and [export verification script](verify.py).
- [Geometry report](build-report.json) and [verification results](verification.json).

The model translates the reference into simpler forms suitable for an RTS art direction: broad sloped hull, segmented side skirts, continuous tracks, separate road wheels, wedge turret armor, hollow muzzle brake, optics, rear engine grilles, chip-interface cover, ochre team panels, and faction chevrons.

## Asset structure and integration

```text
BastionTank
├── HullMesh
└── TurretPivot
    ├── TurretMesh
    └── BarrelPivot
        ├── BarrelMesh
        └── Muzzle
```

- 12,640 triangles across three rigid meshes; 21 material primitives before engine-side optimization.
- Approximate dimensions: 4.38 m wide, 7.85 m long including the gun, 3.20 m tall including antennas. These are stylized proportions, not a real vehicle specification.
- Ground origin; Blender +Y forward / +Z up exports to Godot -Z forward / +Y up.
- In Godot, rotate `TurretPivot` around local Y for yaw and `BarrelPivot` around local X for elevation. `Muzzle` follows both pivots.
- Team panels use the separately named `TeamColor / Bastion ochre` material. The existing template's color-replacement convention has not been wired to this material.
- Editable source nodes are prefixed `Source_` where necessary to distinguish the source hierarchy from the consolidated export hierarchy.
- The export collection is hidden in the Blender review scene to avoid drawing both source and export copies. The GLB contains only the export hierarchy, without studio objects.
- `art/.gdignore` keeps Blender source and review renders out of Godot's asset importer. Only the GLB under `assets/models` is intended for game import.

The existing playable tank scene has not been replaced. Integration still requires choosing gameplay scale, matching collision/selection/navigation bounds, attaching turret aiming and projectile spawning, and testing the asset in Godot.

## Rebuild and verify

Run from the repository root:

```sh
blender --background --factory-startup --python-exit-code 1 --python art/bastion/tank-v1/build.py
blender --background --factory-startup --python-exit-code 1 --python art/bastion/tank-v1/verify.py
```

The build script recreates this version's generated `.blend`, `.glb`, reports, and preview renders. Keep manual edits in a new version or a separate file before rebuilding. The verification script imports the exported GLB, checks its hierarchy/geometry/bounds, exercises both pivots, and renders the imported result using the same studio.

Blender API reference used for the export setup: [glTF export operator](https://docs.blender.org/api/main/bpy.ops.export_scene.html).

## Verification and remaining work

The checks cover GLB structure, self-contained buffers, mesh and triangle counts, nondegenerate finite geometry, round-trip bounds, named pivot hierarchy, muzzle attachment, turret yaw, cannon elevation, and a stationary hull during articulation. Zero-area triangles generated by some thin bevels are removed before export; reimport validation checks that they remain absent.

No Godot executable was found in PATH or installed applications during this task. Engine import, in-engine appearance, and 100-unit performance are therefore unverified.

This review version uses solid PBR materials. It does not yet include an authored texture atlas, final UV layout, baked wear/normal maps, LODs, moving track animation, collision shapes, or gameplay behavior. Material consolidation and LOD work should follow visual approval and profiling; the current material primitive count is not a production performance target.
